\chapter*{Abstract}
\thispagestyle{plain}

In modern recruitment ecosystems, candidates face significant challenges in quantitatively evaluating how well their resumes align with competitive, multi-faceted job descriptions. Existing Applicant Tracking Systems (ATS) predominantly suffer from two polar extremes: (1) brittle string-matching rules that fail to recognize domain synonyms (e.g., rejecting an applicant citing \textit{“ML”} when the employer specifies \textit{“Machine Learning”}), or (2) opaque, non-deterministic commercial Large Language Models (LLMs) that hallucinate scores, generate arbitrary advice, and obscure their underlying decision logic.

To address these critical limitations, this project presents \textbf{AI Resume Analyzer}, an open, mathematically grounded, and transparent \textbf{NLP-Based Intelligent Resume Analysis and Job Matching System}. Developed as an academic laboratory project for \textbf{Introduction to Natural Language Processing (AI532P)}, AI Resume Analyzer implements classical and statistical NLP algorithms as the sole core intelligence. The system accepts resume documents in both \textbf{Portable Document Format (PDF)} and \textbf{Microsoft Word (DOCX)} formats, executing an end-to-end ingestion pipeline comprising layout-aware block extraction, token-safe punctuation shielding (protecting symbols such as \texttt{C++}, \texttt{C\#}, and \texttt{.NET}), NLTK sentence/word tokenization, stopword filtering with technical preservation, WordNet/spaCy morphological lemmatization, spaCy Named Entity Recognition (NER), layout heuristic section boundary detection, and taxonomy-based skill extraction with canonical alias mapping.

For job discovery, the system integrates the \textbf{RapidAPI JSearch API} strictly to query live real-time job listings from global aggregators. Crucially, in strict adherence to selective information retrieval principles, AI Resume Analyzer does not run indiscriminate matching across all retrieved jobs; rather, it executes deep NLP parsing exclusively on the \textbf{single target job} explicitly selected by the user.

Matching is executed using a composite, transparent multi-factor formulation:
$$\text{Overall Match Score} = (0.50 \times \text{TF-IDF Cosine Similarity}) + (0.40 \times \text{Skill Match}) + (0.10 \times \text{Requirement Match})$$

Where Term Frequency–Inverse Document Frequency (TF-IDF) feature vectors with n-grams $(1, 2)$ and sublinear scaling compute directional vector alignment ($\cos\theta$). Personalized recommendations are strictly derived from extracted skill gaps and qualification deltas. Furthermore, AI Resume Analyzer includes an interactive \textbf{Academic Viva Inspection Interface} that renders intermediate NLP traces (tokens, lemmas, entity tags, vector dimensions, and dot-product feature contributions). The complete system has been verified through a 16-test automated unit testing suite, real-world document parsings, live API benchmarks, and an interactive Streamlit presentation dashboard.

\chapter{Introduction}

\section{Background and Motivation}
In modern engineering and technology job markets, the initial screening of employment applications is predominantly mediated by automated algorithms. Over 90\% of Fortune 500 corporations utilize Applicant Tracking Systems (ATS) to filter, rank, and categorize candidates before human recruiters inspect a resume. However, early-stage job seekers, undergraduate engineering students, and career changers often lack transparent tools to evaluate how closely their curricular background, project portfolio, and technical vocabulary mirror the requirements of target industry positions.

Natural Language Processing (NLP), as a branch of computer science and artificial intelligence, provides mathematically sound techniques to parse unstructured text, identify semantic entities, project documents into high-dimensional vector spaces, and compute directional alignment. Developing an automated, deterministic system that uncovers candidate-job compatibility represents an exemplary application of classical information retrieval and computational linguistics.

\section{Problem Statement}
Traditional approaches to automated resume evaluation suffer from severe practical deficiencies:
\begin{enumerate}
    \item \textbf{Brittle Syntactic Matching:} Rudimentary ATS implementations rely on naive substring searching. Under such paradigms, candidate qualifications are penalized due to minor orthographic or alias discrepancies (e.g., an applicant writing \textit{“Scikit-learn”} or \textit{“sklearn”} failing an exact filter for \textit{“scikit learn”}).
    \item \textbf{Opaque Commercial LLMs:} Many modern commercial tools simply forward resume text to external proprietary Large Language Model APIs (e.g., OpenAI ChatGPT). While conversational, these models operate as non-deterministic black boxes: they hallucinate scores, vary numerical outputs between identical runs, fail to expose underlying vector mathematics, and introduce data privacy vulnerabilities.
    \item \textbf{Indiscriminate Computational Waste:} Naive systems attempt to calculate similarity metrics across dozens or hundreds of retrieved job search results simultaneously, exhausting computational resources, exceeding API rate limits, and diluting candidate focus.
\end{enumerate}

\section{Project Objectives}
The objective of this project is to architect, implement, and validate \textbf{AI Resume Analyzer}, an academic-grade NLP system titled \textbf{“NLP-Based Intelligent Resume Analysis and Job Matching System”} for the course \textbf{Introduction to Natural Language Processing (AI532P)}.

The explicit technical objectives comprise:
\begin{itemize}
    \item \textbf{Automated Document Extraction:} Ingest resumes in both PDF and DOCX formats without requiring manual candidate data entry.
    \item \textbf{Robust Linguistic Preprocessing:} Implement token-safe text cleaning that preserves punctuation-sensitive programming tokens (\texttt{C++}, \texttt{C\#}, \texttt{.NET}, \texttt{Node.js}), followed by tokenization, stopword removal, and morphological lemmatization.
    \item \textbf{Structured Candidate Profiling:} Extract Named Entities (\texttt{PERSON}, \texttt{ORG}, \texttt{GPE}, \texttt{DATE}) using spaCy, detect resume sections, and build a structured candidate profile.
    \item \textbf{Live Industry Job Ingestion:} Connect to the \textbf{RapidAPI JSearch API} to retrieve live, current employment openings without calculating match scores indiscriminately.
    \item \textbf{Selective Single-Job Matching:} Allow the candidate to select exactly one target position, executing the NLP pipeline solely on the chosen job description.
    \item \textbf{Mathematically Deterministic Scoring:} Evaluate directional alignment using TF-IDF vector space modeling and Cosine Similarity, combined with taxonomy-normalized skill matching and requirement evaluation.
    \item \textbf{Actionable Feedback:} Generate resume enhancement recommendations derived strictly from detected skill gaps and missing qualifications.
    \item \textbf{Academic Viva Transparency:} Expose an interactive inspector detailing every mathematical and linguistic step for evaluator examination.
\end{itemize}

\chapter{Theoretical Foundations and Methodology}

\section{Vector Space Model and TF-IDF}
To evaluate document relevance mathematically, Gerard Salton et al. established the Vector Space Model. Documents are projected into an orthogonal vector space spanned by vocabulary terms. The composite weight balances local term occurrence with corpus-wide discriminative specificity:

\begin{equation}
\text{TF}(t, d) = 1 + \log(\text{count}(t, d)) \quad \text{for count} > 0
\end{equation}

\begin{equation}
\text{IDF}(t, D) = \log\left(\frac{1 + |D|}{1 + |\{d \in D : t \in d\}|}\right) + 1
\end{equation}

\begin{equation}
\text{TF-IDF}(t, d, D) = \text{TF}(t, d) \times \text{IDF}(t, D)
\end{equation}

AI Resume Analyzer incorporates unigrams and bigrams ($\text{ngram\_range} = (1, 2)$) with sublinear term frequency scaling to prevent keyword stuffing.

\section{Cosine Similarity Metric}
Given resume vector $\mathbf{A}$ and job description vector $\mathbf{B}$, cosine similarity measures directional alignment irrespective of document length differences:

\begin{equation}
\cos(\theta) = \frac{\mathbf{A} \cdot \mathbf{B}}{\|\mathbf{A}\|_2 \|\mathbf{B}\|_2} = \frac{\sum_{i=1}^V A_i B_i}{\sqrt{\sum_{i=1}^V A_i^2} \sqrt{\sum_{i=1}^V B_i^2}}
\end{equation}

\section{Morphological Lemmatization}
Unlike crude stemmers that strip arbitrary suffixes, WordNet lemmatization maps words to their genuine grammatical roots:
\begin{equation*}
\text{developing} \xrightarrow{\text{lemmatize}} \text{develop}, \quad \text{models} \xrightarrow{\text{lemmatize}} \text{model}
\end{equation*}

\section{Multi-Factor Scoring Formulation}
The composite match percentage is computed via a transparent, weighted formula:
\begin{equation}
\text{Overall Score} = (0.50 \times S_{\text{tfidf}}) + (0.40 \times S_{\text{skill}}) + (0.10 \times S_{\text{req}})
\end{equation}

Where $S_{\text{skill}} = \left(\frac{|\text{Resume Skills} \cap \text{Job Skills}|}{|\text{Job Skills}|}\right) \times 100$, and $S_{\text{req}}$ evaluates candidate compliance with required education degrees and minimum experience years.

\chapter{System Architecture and Implementation}

\section{Document Parsing Subsystem}
\begin{itemize}
    \item \textbf{PDF Parsing:} Built using PyMuPDF (\texttt{pymupdf}). Block extraction preserves vertical ordering and multi-column document structures.
    \item \textbf{DOCX Parsing:} Built using \texttt{python-docx}. Extracts both paragraph content and tabular layouts.
\end{itemize}

\section{Token Protection Engine}
Standard tokenizers break tokens like \texttt{C++} into \texttt{C}, \texttt{+}, \texttt{+}. AI Resume Analyzer employs lookbehind-safe regex shielding:
\begin{verbatim}
PROTECTED_TERMS = {
    "c++": "CPP_TOKEN",
    "c#": "CSHARP_TOKEN",
    ".net": "DOTNET_TOKEN",
    "node.js": "NODEJS_TOKEN"
}
\end{verbatim}

\section{External Job API Integration}
RapidAPI JSearch (\texttt{https://jsearch.p.rapidapi.com/search-v2}) retrieves live job opportunities. The system employs a 60-second HTTP timeout and an automatic fallback to the high-speed \texttt{/search} endpoint to ensure continuous availability during peak traffic periods.
